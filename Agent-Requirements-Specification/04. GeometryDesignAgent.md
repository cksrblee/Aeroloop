# Agent_Requirements_Specification

### Agent Name
GeometryDesignAgent

### Agent Overview
GeometryDesignAgent translates selected aircraft configuration and geometry design parameters into a traceable parametric 3D geometry model. It uses OpenVSP's Python API to generate aircraft components from predefined topology templates, saves the native `.vsp3` model, exports simulation-ready mesh artifacts such as `.stl`, validates the generated mesh, and produces a geometry manifest linking the generated artifacts back to upstream requirements, sizing results, and CCL/MoC evidence needs.

The agent does not determine aerodynamic, structural, or certification validity. It only generates and validates geometry artifacts for downstream simulation, analysis, and compliance evidence workflows.

### Workflow Position
- **Upstream:** `RequirementReasoningAgent`, `AircraftCandidateGenerator`, `SizingEngine`, `ConfigurationDesignAgent`
- **Downstream:** `SimulationAgent`, `MeshValidationAgent`, `AerodynamicAnalysisAgent`, `CertificationComplianceAgent`, `ReportGenerationAgent`

### Functional Requirements
| ID | Requirement |
| --- | --- |
| GDA-FR-01 | The agent shall read a `GeometryDesignRequest` containing selected aircraft candidate, configuration ID, geometry template, design parameters, and export options. |
| GDA-FR-02 | The agent shall select a geometry template based on `vehicle_type` and `geometry_template`. |
| GDA-FR-03 | The agent shall validate all required geometry parameters before OpenVSP execution. |
| GDA-FR-04 | The agent shall normalize units and reject invalid physical dimensions such as negative length, zero chord, or negative rotor radius. |
| GDA-FR-05 | The agent shall apply default template parameters only when allowed by config and record all defaults in `warnings` and `assumptions`. |
| GDA-FR-06 | The agent shall generate OpenVSP geometry components such as fuselage, wing, rotor disk proxy, boom, tail, and landing gear proxy depending on template type. |
| GDA-FR-07 | The agent shall save the native OpenVSP `.vsp3` file. |
| GDA-FR-08 | The agent shall export selected geometry sets to `.stl`. |
| GDA-FR-09 | The agent should optionally export `.step`, `.iges`, `.obj`, or `.glb` when enabled by export options. |
| GDA-FR-10 | The agent shall generate a `GeometryManifest` describing generated components, parameters, artifact paths, and traceability links. |
| GDA-FR-11 | The agent shall validate the exported mesh using basic file and mesh checks. |
| GDA-FR-12 | The agent shall return `GeometryDesignResult` with status, artifacts, validation report, warnings, and errors. |
| GDA-FR-13 | The agent shall not claim aerodynamic, structural, or certification validity of the generated geometry. |
| GDA-FR-14 | The agent shall link generated geometry artifacts to upstream requirements, design parameters, and candidate aircraft IDs. |
| GDA-FR-15 | The agent shall produce compliance artifact links for CCL/MoC workflows when relevant CCL item IDs are provided. |

### Non-Functional Requirements
| ID | Requirement |
| --- | --- |
| GDA-NFR-01 | The agent shall be deterministic for identical input, config, OpenVSP version, and template version. |
| GDA-NFR-02 | The agent shall not mutate shared output directories; each run must write to an isolated run-specific directory. |
| GDA-NFR-03 | The agent shall record OpenVSP version, Python version, template version, and schema version. |
| GDA-NFR-04 | The agent shall fail safely when OpenVSP is unavailable and return a structured error. |
| GDA-NFR-05 | The agent shall not hallucinate missing geometry parameters; defaults must come from template config only. |
| GDA-NFR-06 | The agent output shall pass Pydantic schema validation. |
| GDA-NFR-07 | The agent shall preserve traceability from design requirements to geometry artifacts. |
| GDA-NFR-08 | The agent shall separate geometry generation from aerodynamic/structural validation. |
| GDA-NFR-09 | The agent shall support headless execution in CI or server environments. |
| GDA-NFR-10 | The agent shall produce reproducible logs for debugging and Langfuse/experiment tracking. |

### Constraints & Shall Nots
GeometryDesignAgent shall not:
1. Decide certification compliance.
2. Decide aerodynamic validity.
3. Modify final requirements.
4. Invent missing design parameters outside template-defined defaults.
5. Run high-fidelity CFD.
6. Treat STL generation as proof of design feasibility.
7. Use customer requirements directly without a design/configuration parameter layer.

### OpenVSP Execution Policy
1. Each run must start with a clean OpenVSP model.
2. The agent must call OpenVSP update after setting parameters.
3. The agent must save .vsp3 before exporting mesh artifacts.
4. The agent must export only the intended geometry set.
5. If mesh export creates temporary MeshGeom objects, the agent must clean them up after export when necessary.
6. All generated files must be written under a run-specific output directory.
7. The agent must record OpenVSP version if available.

### Error Handling Policy
- If the `openvsp` module cannot be imported, the agent must return a clear error stating the dependency is missing (`failed`).
- Required parameter missing -> `failed` or `success_with_warnings` depending on default allowance.
- Negative dimension -> `failed`.
- Unknown vehicle_type -> `failed`.
- Template not found -> `failed`.
- Output directory not writable -> `failed`.
- `.vsp3` save failed -> `failed`.
- `.stl` export failed -> `failed`.
- STL exists but Open3D load failed -> `success_with_warnings` or `failed` based on validation options.
- Mesh empty -> `failed`.
- No generated components -> `failed`.

Output errors must be structured as:
```json
{
  "error_code": "INVALID_DIMENSION",
  "message": "wingspan_m must be greater than 0.",
  "field": "design_parameters.wingspan_m",
  "recoverable": false
}
```

### Evaluation Criteria
| Metric | Description |
| --- | --- |
| Schema Validity | Output matches `GeometryDesignResult` schema |
| File Generation Rate | `.vsp3`, `.stl`, manifest generated |
| Parameter Coverage | Required template parameters applied |
| Default Usage Rate | Number of defaulted parameters |
| Mesh Loadability | STL can be loaded by Open3D |
| Mesh Basic Quality | Non-empty vertices/faces, valid bounding box |
| Traceability Completeness | Parameter sources and artifact links generated |
| Compliance Artifact Readiness | CCL/MoC artifact links generated when context exists |
| Reproducibility | Same input generates same artifact manifest |
| Error Handling Correctness | Invalid inputs fail with structured errors |

### Test Cases
- **Normal Case 1:** fixed_wing template with complete parameters → .vsp3 and .stl generated
- **Normal Case 2:** lift_cruise_vtol template with rotor proxies → component list includes rotors
- **Missing Optional Parameter:** tip_chord_m missing → template default applied and warning logged
- **Missing Required Parameter:** fuselage_length_m missing and no default → failed
- **Invalid Dimension:** negative wingspan → failed
- **Unknown Vehicle Type:** vehicle_type=unknown → failed
- **Mesh Validation:** STL generated but not watertight → success_with_warnings
- **Traceability:** parameter_sources are included → trace_links generated
- **Compliance Context:** ccl_item_ids are provided → compliance_artifact_links generated
- **Output Isolation:** two different run_id values → artifacts saved to separate directories
