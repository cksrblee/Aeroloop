# Agent_Requirements_Specification

### Agent Name
SizingAgent

### Agent Overview
The SizingAgent is a deterministic low-fidelity engineering calculator for preliminary aircraft sizing. It receives a MissionProfile, FinalRequirementSet, and AircraftCandidate, selects an aircraft-type-specific sizing template, and computes preliminary weight, energy, power, geometry, and simulation parameters.

The agent produces SizingResult, EnergySizingResult, PowerSizingResult, GeometryParameterSet, PerformanceEstimate, and SimulationParameterSet. These outputs bridge abstract requirements and downstream physical artifacts such as OpenVSP geometry, flight simulation parameters, and preliminary CCL/MoC analysis evidence.

The SizingAgent does not perform high-fidelity aerodynamic analysis, structural validation, or certification approval. All calculations are template-based and must be reported with assumptions, limitations, traceability, and deterministic formula references.

### Functional Requirements
| ID | Requirement |
| --- | --- |
| SIZA-FR-08 | The agent shall select a sizing template based on `aircraft_type` and `template_id`. |
| SIZA-FR-09 | The agent shall extract relevant numeric constraints from `FinalRequirementSet`, such as passenger count, reserve battery, obstacle clearance, and speed constraints. |
| SIZA-FR-10 | The agent shall perform iterative MTOW estimation until convergence or max iteration count is reached. |
| SIZA-FR-11 | The agent shall compute a weight breakdown including payload, battery, empty structure, propulsion, avionics, margin, and MTOW. |
| SIZA-FR-12 | The agent shall compute energy sizing including mission energy, reserve energy, required battery capacity, and estimated arrival battery. |
| SIZA-FR-13 | The agent shall compute power sizing using template-specific power loading assumptions. |
| SIZA-FR-14 | The agent shall compute rotor sizing for VTOL/helicopter/multirotor templates. |
| SIZA-FR-15 | The agent shall compute wing sizing for small_aircraft and lift_cruise_vtol templates. |
| SIZA-FR-16 | The agent shall generate a `GeometryParameterSet` for GeometryDesignAgent. |
| SIZA-FR-17 | The agent shall generate a `SimulationParameterSet` for SimulationAgent and PathPlanningAgent. |
| SIZA-FR-18 | The agent shall produce a `FeasibilityReport` explaining whether each major requirement is satisfied. |
| SIZA-FR-19 | The agent shall generate trace links from requirements to sizing outputs. |
| SIZA-FR-20 | The agent shall generate CCL/MoC analysis evidence links when compliance context is provided. |

### Non-Functional Requirements
| ID | Requirement |
| --- | --- |
| SIZA-NFR-04 | The agent shall never silently fallback to a different aircraft template unless `allow_template_fallback=true`. |
| SIZA-NFR-05 | The agent shall record all defaulted values as assumptions. |
| SIZA-NFR-06 | The agent shall record all formula versions and template versions used in the calculation. |
| SIZA-NFR-07 | The agent shall be reproducible for identical input, template, and config. |
| SIZA-NFR-08 | The agent shall separate engineering calculation from LLM-generated explanation. |
| SIZA-NFR-09 | The agent shall not claim certification compliance from low-fidelity sizing results. |
| SIZA-NFR-10 | The agent shall fail safely if required mission or template data is unavailable. |
| SIZA-NFR-11 | The agent shall support unit testing for each calculator function independently. |
| SIZA-NFR-12 | The agent shall expose calculation traces for debugging and review. |

### Output Specification
The output consists of a wrapper `SizingAgentResult` containing:
- `sizing_result` (with WeightBreakdown)
- `energy_sizing_result`
- `power_sizing_result`
- `geometry_parameter_set`
- `performance_estimate`
- `simulation_parameter_set`
- `feasibility_report`
- `trace_links`
- `compliance_artifact_links`

### Tool and Knowledge Source Usage
- `sizing_calculator`: Internal deterministic logic method to calculate sizing variables, using strict iteration bounds.

### Reasoning and Decision Policy
LLM is restricted to generating assumptions, limitations, and feasibility summaries. It MUST NOT compute or modify MTOW, geometry, or power outputs. It must not claim actual certification compliance.

### Error Handling Policy
- `aircraft_type` unknown: fail (unless `allow_template_fallback=True`)
- `template_id` missing: select based on `aircraft_type`, generate warning
- `passenger_count` missing: default to 1, generate assumption
- `mission_distance_km` missing: default minimum or flag `needs_distance_estimation`
- negative distance / capacity: fail
- MTOW exceeds template max: `mission_feasible = False`
- Iteration not converged: `success_with_warnings` or fail based on config
- Wing/Disk loading missing for corresponding type: fail

### Evaluation Criteria
- Weight Balance Validity
- Energy Consistency
- Template Correctness
- Convergence Status
- Geometry Parameter Completeness
- Simulation Parameter Completeness
- Feasibility Check Coverage
- Traceability Completeness
- CCL/MoC Readiness
- No Silent Fallback
