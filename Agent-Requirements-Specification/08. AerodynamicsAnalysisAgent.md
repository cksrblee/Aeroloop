# Agent_Requirements_Specification

### Agent Name

AerodynamicsAnalysisAgent

### Agent Abbreviation

AAA

### Agent Overview

The `AerodynamicsAnalysisAgent` analyzes the aerodynamic and mass-related characteristics of the aircraft geometry generated by `GeometryDesignAgent`. It consumes OpenVSP geometry artifacts, geometry parameters, sizing outputs, and simulation parameter sets, then performs low-fidelity aerodynamic and mass property analyses using OpenVSP/VSPAERO and related analysis tools.

The agent estimates aerodynamic coefficients, lift/drag characteristics, stability-related metrics, reference geometry values, center of gravity, moments of inertia, and mass property summaries. Its outputs are used by downstream simulation, requirement verification, and certification compliance workflows.

The `AerodynamicsAnalysisAgent` does not perform high-fidelity CFD, structural analysis, or final certification approval. Its results are preliminary engineering analysis outputs intended for early-stage concept design, trade study, simulation parameter refinement, and preliminary CCL/MoC evidence generation.

### Workflow Position

### Upstream

* `RequirementReasoningAgent`
  * Provides `FinalRequirementSet`
  * Provides aerodynamic, stability, performance, or certification-related requirements
* `AircraftCandidateGenerator`
  * Provides selected aircraft candidate and aircraft type
* `SizingAgent`
  * Provides `SizingResult`
  * Provides `WeightBreakdown`
  * Provides `GeometryParameterSet`
  * Provides `SimulationParameterSet`
* `GeometryDesignAgent`
  * Provides `.vsp3` file
  * Provides `.stl` file
  * Provides `GeometryManifest`
  * Provides `MeshValidationReport`
* `RegulatoryRequirementAgent`
  * Provides CCL/MoC candidate items when aerodynamic or mass-property evidence is required

### Downstream

* `SimulationAgent`
  * Consumes refined aerodynamic and mass properties
* `PathPlanningAgent`
  * May consume updated performance constraints
* `RuntimeVerificationAgent`
  * Uses aerodynamic/performance limits for rule evaluation
* `CertificationComplianceAgent`
  * Consumes aerodynamic and mass analysis artifacts as preliminary MoC evidence
* `ReportGenerationAgent`
  * Consumes aerodynamic summaries, limitations, plots, and analysis artifacts

### Core Responsibility

The agent converts geometry artifacts into preliminary aerodynamic and mass-property analysis outputs.

```text
GeometryArtifact + SizingResult + SimulationParameterSet
→ Aerodynamic Analysis Setup
→ VSPAERO / OpenVSP Analysis Execution
→ Aerodynamic Coefficients
→ Mass Properties
→ Stability / Feasibility Checks
→ Analysis Artifacts
→ CCL/MoC Evidence Links
```

### Functional Requirements

| ID        | Requirement                                                                                                                                                                            |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AAA-FR-01 | The agent shall read OpenVSP geometry artifacts generated by `GeometryDesignAgent`, especially `.vsp3` files.                                                                          |
| AAA-FR-02 | The agent shall read `GeometryManifest`, `GeometryParameterSet`, `SizingResult`, and `SimulationParameterSet` when available.                                                          |
| AAA-FR-03 | The agent shall validate that required geometry artifacts exist before analysis execution.                                                                                             |
| AAA-FR-04 | The agent shall determine the appropriate aerodynamic analysis mode based on aircraft type and analysis purpose.                                                                       |
| AAA-FR-05 | The agent shall set aerodynamic reference values such as reference area, reference span, reference chord, and moment reference point.                                                  |
| AAA-FR-06 | The agent shall define an aerodynamic analysis case matrix including angle of attack, sideslip angle, Mach number or speed, altitude, and Reynolds-related assumptions when available. |
| AAA-FR-07 | The agent shall execute low-fidelity aerodynamic analysis using OpenVSP/VSPAERO or an equivalent configured backend.                                                                   |
| AAA-FR-08 | The agent shall extract aerodynamic coefficients such as CL, CD, CM, CY, Cl, and Cn where available.                                                                                   |
| AAA-FR-09 | The agent shall generate aerodynamic performance summaries such as lift curve, drag polar, L/D estimate, and trim-related indicators when supported by the backend.                    |
| AAA-FR-10 | The agent shall perform or request OpenVSP mass property analysis when density and component mass assumptions are available.                                                           |
| AAA-FR-11 | The agent shall compute or extract center of gravity, moments of inertia, total mass, and component-level mass contribution when available.                                            |
| AAA-FR-12 | The agent shall compare mass properties against `SizingResult` and flag inconsistencies beyond tolerance.                                                                              |
| AAA-FR-13 | The agent shall evaluate whether the generated geometry appears compatible with basic performance assumptions from `SizingAgent`.                                                      |
| AAA-FR-14 | The agent shall identify aerodynamic analysis limitations such as missing rotor modeling, simplified wake model, missing viscous drag, or invalid geometry intersections.              |
| AAA-FR-15 | The agent shall output all generated analysis files, plots, logs, and result tables as structured artifacts.                                                                           |
| AAA-FR-16 | The agent shall generate `AerodynamicsAnalysisResult` in a strict JSON schema.                                                                                                         |
| AAA-FR-17 | The agent shall generate trace links from upstream requirements, geometry artifacts, sizing results, and analysis outputs.                                                             |
| AAA-FR-18 | The agent shall generate preliminary CCL/MoC evidence links when compliance context is provided.                                                                                       |
| AAA-FR-19 | The agent shall not claim certification compliance from low-fidelity aerodynamic analysis results.                                                                                     |
| AAA-FR-20 | The agent shall produce a human-readable explanation of assumptions, limitations, analysis setup, and major results.                                                                   |

### Non-Functional Requirements

| ID         | Requirement                                                                                                                              |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| AAA-NFR-01 | The agent shall use deterministic analysis tools and explicit configuration rather than LLM-generated aerodynamic values.                |
| AAA-NFR-02 | The agent shall not invent aerodynamic coefficients, stability derivatives, CG values, or moments of inertia.                            |
| AAA-NFR-03 | The agent shall separate analysis execution from LLM-based explanation generation.                                                       |
| AAA-NFR-04 | The agent shall produce reproducible results for identical input geometry, analysis configuration, OpenVSP version, and solver settings. |
| AAA-NFR-05 | The agent shall record OpenVSP version, VSPAERO version if available, analysis backend, template version, and schema version.            |
| AAA-NFR-06 | The agent shall write outputs to a run-specific isolated output directory.                                                               |
| AAA-NFR-07 | The agent shall fail safely with structured errors if required tools or geometry artifacts are missing.                                  |
| AAA-NFR-08 | The agent shall clearly mark all results as low-fidelity preliminary engineering estimates.                                              |
| AAA-NFR-09 | The agent shall preserve traceability between geometry, sizing, aerodynamic analysis, mass analysis, requirements, and CCL/MoC items.    |
| AAA-NFR-10 | The agent shall support headless execution in server or CI environments when toolchain installation permits.                             |
| AAA-NFR-11 | The agent shall output schema-valid JSON for every execution state, including failure states.                                            |
| AAA-NFR-12 | The agent shall support unit tests for input validation, schema validation, artifact detection, and result parsing.                      |

### Tool and Knowledge Source Usage

| Tool / Source                  | Usage                                                                                                           |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| OpenVSP Python API             | Load `.vsp3`, set reference values, run geometry-related analyses, execute mass property analysis when possible |
| VSPAERO                        | Low-fidelity aerodynamic coefficient estimation                                                                 |
| OpenVSP Mass Properties        | Center of gravity, mass, component contribution, and inertia estimation                                         |
| OpenVSP Parasite Drag Analysis | Optional drag estimation when enabled                                                                           |
| GeometryManifest               | Component-level geometry metadata                                                                               |
| SizingResult                   | MTOW, weight assumptions, and sizing reference values                                                           |
| SimulationParameterSet         | Cruise speed, altitude, and performance conditions                                                              |
| FinalRequirementSet            | Aerodynamic, stability, mass, and performance-related requirements                                              |
| CCL/MoC Context                | Links analysis outputs to preliminary compliance evidence                                                       |

### Reasoning and Decision Policy

### Deterministic Analysis Policy

The agent must not generate aerodynamic coefficients or mass properties from an LLM. All numerical aerodynamic and mass-property outputs must come from:

* OpenVSP analysis
* VSPAERO results
* deterministic post-processing
* explicit input data
* configured fallback values marked as assumptions

The LLM may only be used to:

* summarize analysis results
* explain assumptions
* explain limitations
* format the final JSON or report text
* generate human-readable descriptions of deterministic outputs

### Analysis Fidelity Policy

The agent must classify results by fidelity level:

| Fidelity     | Meaning                                                                            |
| ------------ | ---------------------------------------------------------------------------------- |
| `conceptual` | Very rough estimates from geometry and sizing values                               |
| `low`        | VSPAERO or template-based low-fidelity analysis                                    |
| `medium`     | More detailed OpenVSP/VSPAERO setup with sweeps and stability settings             |
| `high`       | Reserved for external CFD or higher-fidelity solvers; not supported in initial PoC |

Initial PoC default:

```json
{
  "analysis_fidelity": "low",
  "analysis_backend": "openvsp_vspaero"
}
```

### Aircraft-Type Policy

The agent shall support aircraft-type-specific behavior.

| Aircraft Type      | Analysis Policy                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------ |
| `small_aircraft`   | Wing-based VSPAERO analysis, drag polar, lift curve, mass properties                       |
| `small_helicopter` | Mass properties and simplified rotorcraft aerodynamic notes; VSPAERO may be limited        |
| `lift_cruise_vtol` | Wing/body analysis plus rotor/propulsion limitations explicitly flagged                    |
| `multirotor`       | Mass properties and simplified drag/rotor limitations; VSPAERO results may be incomplete   |
| `tiltrotor_vtol`   | Preliminary analysis only; transition and rotor interaction must be flagged as limitations |

### Reference Geometry Policy

The agent must determine and record:

* reference area
* reference span
* reference chord
* moment reference point
* aerodynamic coordinate convention
* units

Priority for reference values:

```text
1. Explicit analysis_config values
2. GeometryParameterSet values
3. GeometryManifest values
4. SizingTemplate defaults
5. Fail or warn if unavailable
```

### Mass Property Policy

The agent may run mass property analysis only if sufficient component density, material, or mass assignment data exists.

If component density data is missing, the agent shall:

* return `mass_analysis_available = false`, or
* use SizingAgent weight breakdown as a comparison reference, not as computed OpenVSP mass

The agent must not treat incomplete component mass assumptions as final aircraft mass properties.

### CCL/MoC Policy

The agent may provide preliminary evidence candidates for CCL/MoC workflows.

Examples:

| CCL Item                    | MoC Type              | Evidence from AAA                             |
| --------------------------- | --------------------- | --------------------------------------------- |
| Aerodynamic characteristics | Analysis              | VSPAERO result tables, drag polar, lift curve |
| Mass and balance            | Analysis              | Mass properties output, CG, inertia           |
| Stability characteristics   | Analysis / Simulation | Stability summary, moment trends              |
| Performance assumptions     | Analysis              | CL/CD estimates, L/D estimate                 |
| Design review               | Drawing / Analysis    | Geometry reference values and analysis setup  |

The agent must label these outputs as:

```text
preliminary_analysis_evidence
```

not as:

```text
certification_approved_evidence
```

### Error Handling Policy

| Error Case                                    | Required Behavior                                                                          |
| --------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `.vsp3` file missing                          | Return `status = failed` with `GEOMETRY_FILE_NOT_FOUND`                                    |
| OpenVSP module unavailable                    | Return `status = failed` with `OPENVSP_UNAVAILABLE`                                        |
| VSPAERO execution unavailable                 | Return `status = success_with_warnings` if mass analysis can still run, otherwise `failed` |
| Invalid reference area/span/chord             | Return `failed` unless configured fallback exists                                          |
| Solver non-convergence                        | Return `success_with_warnings`; include solver log path and non-convergence warning        |
| Empty result file                             | Return `failed`                                                                            |
| Mass property analysis failed                 | Continue aerodynamic analysis if possible; set `mass_analysis_available = false`           |
| Component density missing                     | Warn and skip OpenVSP mass analysis or use sizing reference only                           |
| Unknown aircraft type                         | Return `failed` unless `allow_aircraft_type_fallback = true`                               |
| Geometry intersections cause analysis failure | Return `failed` or `success_with_warnings` depending on severity                           |
| No CCL context provided                       | Continue analysis and omit compliance links                                                |

### Evaluation Criteria

| Metric                         | Description                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------ |
| Schema Validity                | Output must conform to `AerodynamicsAnalysisResult` schema                     |
| Artifact Availability          | Required result files and logs must be generated or error-reported             |
| Deterministic Result Integrity | Coefficients and mass properties must come from solver or deterministic parser |
| Reference Geometry Validity    | Reference area, span, chord, and moment reference must be recorded             |
| Solver Execution Success       | VSPAERO or configured backend completes successfully                           |
| Mass Analysis Success          | Mass properties are computed when sufficient data is available                 |
| Result Parsing Accuracy        | CL, CD, CM, CG, inertia, and summary metrics are parsed correctly              |
| Traceability Completeness      | Geometry, sizing, and requirement links are generated                          |
| CCL/MoC Readiness              | Analysis artifacts are linked to relevant CCL/MoC items when context exists    |
| Limitation Transparency        | Solver limitations and unsupported effects are clearly listed                  |
| No Hallucinated Results        | LLM must not invent numerical aerodynamic or mass values                       |

### Core Internal Pipeline

```text
1. Validate AerodynamicsAnalysisRequest
2. Verify geometry artifact existence
3. Load geometry metadata and sizing outputs
4. Select analysis backend and fidelity level
5. Resolve aerodynamic reference values
6. Build VSPAERO case matrix
7. Execute aerodynamic analysis
8. Parse aerodynamic coefficients
9. Run mass property analysis if configured and possible
10. Parse mass properties
11. Compare mass properties with SizingResult
12. Generate aerodynamic summary
13. Generate feasibility assessment
14. Save result artifacts and plots
15. Generate trace links
16. Generate CCL/MoC evidence links
17. Return AerodynamicsAnalysisResult
```

### Agent Prompt Policy

If an LLM is used, it must follow this instruction:

```text
You are the explanation layer of AerodynamicsAnalysisAgent.

You must not invent aerodynamic coefficients, mass properties, stability derivatives, or solver outputs.
You may only summarize deterministic outputs produced by OpenVSP, VSPAERO, mass property analysis, or explicit input schemas.
You must clearly state assumptions and limitations.
You must not claim certification compliance.
You must return JSON that conforms to the AerodynamicsAnalysisResult schema.
```

### Acceptance Criteria

The first implementation of `AerodynamicsAnalysisAgent` is considered complete when:

```text
1. It accepts AerodynamicsAnalysisRequest.
2. It validates the existence of the `.vsp3` geometry file.
3. It resolves reference area, span, and chord.
4. It builds an analysis case matrix.
5. It supports a mock backend for testing without OpenVSP.
6. It supports OpenVSP/VSPAERO execution when available.
7. It parses at least CL, CD, and CM from aerodynamic results when available.
8. It runs or attempts mass property analysis when configured.
9. It returns schema-valid AerodynamicsAnalysisResult.
10. It records assumptions, warnings, limitations, and errors.
11. It generates trace links from geometry and sizing results.
12. It generates CCL/MoC evidence links when compliance context is provided.
13. It never fabricates aerodynamic or mass-property values.
```
